   会错误报告零步。`8b383db` 改为使用原生终态、落盘动作及执行回执计数，缺失时标明 lower_bound/unknown。

   `8b383db` 在派发前与失败返回分支补齐检查，测试覆盖从 59 次命令开始的连续失败。

   `573549c` 在派发前检查终态，立即返回 episode_over；协议测试确认不会写入新请求。

## 实验结论的边界

堆叠开发回合成功，179 控制步，不能由这一例推断总体优于 HexaShell。
叠衣 v1 成功布局 1 用 399 步，相同 HexaShell 布局为 479 步；但两例 v1 的耗时和 token 明显更多。
因此当前证据支持部分成功轨迹更短，不支持整体效率更好。完整统计见叠衣对比记录。
