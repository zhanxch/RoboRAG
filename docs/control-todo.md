# RoboRAG：MHS + CaP 最小闭环

分支：`feat/mhs-cap-minimal`。2026-10-23。
从已提交基线 `79cbc94` 独立开发；主工作区中未提交的队列控制和实验工作不属于本分支。

## 第一阶段的目标

一个大模型编写可执行程序，程序通过 RoboRAG 自己定义的具身 MHS 调用本体已有技能，
执行结果回到同一个模型，由它继续或修正程序。

MCP 提供连接、能力发现和工具调用；MHS 定义机器人能力的具体语义：
操作哪只手、什么坐标系和单位、允许什么动作、返回什么状态与执行结果。
小脑是本地实现的运动和夹爪技能。第一版不需要第二个监督模型。

## 最小实现与验收

- [x] 独立分支、独立工作区，保留原 RAG 基线。
- [x] `roborag-mhs/0.1` 设备能力、观测和阻塞 skill 契约。
- [x] MCP stdio 服务和客户端：发现、读取状态、移动、夹爪、停止。
- [x] CaP Python 子集：变量、条件、有限循环、状态读取和连续 skill 调用。
- [x] 单模型 harness：程序执行 → 实际反馈 → 继续/修正；保存本回合工作记忆和日志。
- [x] 模型入口支持显式 model/effort，默认 Astra xhigh；不固定模型分工。
- [x] 合成设备经真实 MCP 的完整闭环，以及一次动作拒绝后的恢复。
- [x] RoboDojo 环境对象的本地 driver：平移、保持姿态、显式夹爪、执行步数和跟踪中断。
- [ ] 在原生 RoboDojo 生命周期中运行该 driver，并完成 RGB + 大模型的短任务。
- [ ] 冻结一个可复现的真实模型 / 原生仿真最小案例，保留失败和成本。

MHS/程序/反馈的集成通过不代表真实 manipulation 成功。
RoboDojo driver 目前通过接口替身测试，尚未完成原生仿真和 MCP 服务集成。
不能把合成设备的物体坐标与 held 标签当成 RoboDojo 可用的观测。

## 等闭环稳定后再做

1. **经验写入**：每个任务结束，harness 保留原始程序和执行证据；由同一个模型提出可复用经验。
2. **检索时机**：先比较规划前、失败后和模型主动请求；不默认每个运动步都检索。
3. **经验维护**：先实现来源、适用 skill 版本、去重和人工可检查的更新，再讨论自动淘汰。
4. **扩展本体**：通过新的 MHS driver 接入其他设备，检查哪些程序和经验可复用。

双模型监督、异步队列、复杂图结构 guidance 和额外感知模块都不作为第一版前置条件。
当前目标是让协议与闭环清楚、可运行、可替换；RAG 的触发和维护留作下一阶段研究。
