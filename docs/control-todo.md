## 设计原则

- 保持三层方向：**Astra xhigh** 制定任务计划，**Luna xhigh** 监督、在授权范围内推进与修正，**本体小脑**执行轨迹与本地保护。双模型是否更省时、省钱，需要与同一执行器上的 Astra 单模型对照验证。
- GPT 决定目标、操作臂、任务阶段、抓取/释放意图和恢复策略。小脑可以推进已授权轨迹的路径点、完成明确下发的夹爪命令、触发停止；不能自行选择新的任务阶段或目标。
- 将**任务计划、当前阶段授权、实际执行进度**分开保存。高层计划可覆盖整个任务，几何轨迹只承诺当前有足够观测支持的一段；不能要求首次看图就规划出整个接触过程的可靠坐标。
- 正常自由空间运动由本地连续执行；语义检查点由 Luna 判断；异常先由本地停止或保持，再交给 GPT。检查点密度按风险和证据需求配置，不按每个插值点调用模型。
- 关闭 RAG 不等于删除状态和记忆：计划、最新观察、回执、未处理事件和当前回合必要事实始终保留。检索历史经验是可选能力。
- 优先复用已验证的 RoboDojo/IK/控制设施，先打通最小闭环。MCP 封装、复杂轨迹优化和新视觉模块按需要增加，不作为第一轮验证的统一前置条件。
- 本文第一阶段针对仿真。所有“停止”“实时”“感知”能力都要写清实现边界；仿真保护通过不代表已具备真机安全能力。

## 2026-10-21 审查基线：已核实的限制

- **审查时没有双模型链路。** 当时[策略入口](../src/roborag/robodojo_policy.py)与 [CLI 传输](../src/roborag/transports/codex_cli.py)固定使用 `gpt-6-astra`；[桥接服务](../src/roborag/transports/responses_bridge.py)只接受一个 `act` 工具。原有启动配置 `--effort` 默认 `medium`。10-23 已解除模型硬编码，但尚未接入 Astra/Luna 角色监督和设备工具集。
- **RAG 已经可关闭。** [启动器](../scripts/run_episode.py)支持 `--mode zero`，但默认是 `dual`；无 RAG 的基础策略仍保留执行历史。后续应为新控制架构明确默认配置，保留现有实验条件。
- **`hybrid` 是动作展开原型。** [控制配置](../src/roborag/control_profiles.py)仅允许瓶子入桶任务；[实现](../src/roborag/continuous_policy.py)通过提示词要求 3–6 个语义位置、近物时 4–8 行动作。模式、阶段和路线没有独立状态机，精细模式的 1 cm 限制、transit 不闭爪等主要靠提示词，尚未成为按模式强制检查的契约。
- **展开会截断，尚无剩余队列。** `expand_waypoint_actions` 返回最多 32 步的列表。最小复核中，4 行各 0.30 m 的同向位移申请了 1.20 m，实际返回 32 步、合计 0.96 m；未返回剩余进度。上游回执又以转换后的长度计数，不能完整描述原始稀疏计划的余量。此例只证明软件截断，不是可达性或仿真运动试验。
- **当前执行是同步分块。** 本地依赖 `vendor/RoboICL/roboicl/rollout.py` 先阻塞等待 `get_action`，再逐条 `take_action`，每步还同步回传观察。模型等待期间该循环不推进动作。协议动作频率是 25 Hz，32 步只对应名义上 1.28 秒仿真时间，不能据此声称能覆盖模型响应时间或达到墙钟实时执行。
- **坐标与反馈有明确局限。** 上游 `dialogue_policy.py` / `astra_policy.py` 约定 EE 为 `link6`，不是指尖/TCP；位置以环境原点为基准、轴向与 world 对齐，姿态为 `[w,x,y,z]`，旋转增量是 world 系旋转向量、左乘，非欧拉角。`ee_joint_state` 是上次夹爪开合指令，不是实测开度；`action_feedback.py` 的跟踪保护只检查臂跟踪残差，不证明碰撞检测或抓取成功。

截至 2026-10-21 核查，MHS 官网仍标为申请制研究预览；官方介绍包括设备描述，以及经 MCP、CLI、代码接口操作设备。这里借鉴“能力可发现、约束可读取、操作可组合”，先定义项目自己的设备契约，不宣称 MHS 兼容。MCP 是工具连接协议，也不提供运动正确性或实时保障。[MHS 官方介绍](https://www.anthropic.com/news/model-hardware-standard-research-preview)、[MHS 官网](https://www.modelhardwarestandard.com/)、[MCP 2025-11-25 规范](https://modelcontextprotocol.io/specification/2025-11-25)。

### 能力、观测与动作契约

- [ ] 从适配器与实际配置生成版本化 `robot_capabilities`：机器人/机械臂/末端标识、受控 link 与 TCP 变换、支持的动作类型、参考系、单位、控制周期、工作空间与运动约束、可用传感器和停止能力。未知/未支持项显式标记，不能只写一个 schema 就视为能力存在。
- [ ] 统一状态快照：`episode_id`、`state_seq`、仿真步/时间、接收端单调时钟、相机采样时刻、标定版本、本体状态、目标估计及来源/置信度、控制器状态。区分 measured / estimated / commanded / unavailable；夹爪指令与实测开度必须分字段。
- [ ] 第一版计划使用带 `frame_id` 的绝对 EE 目标位姿，适配器复用现有位姿/IK 接口；保留旧增量接口用于基线。增量转绝对目标只做一次，写清起始快照、累计方式和旋转约定，不能在续接时重新从零累加同一组位移。
- [ ] 区分 `move_segment` 与显式夹爪命令。自由空间轨迹默认保持夹爪目标；抓取/释放必须绑定阶段授权和观测前置条件，不能隐含在轨迹尾部。精细动作块也必须有模式、有效期、位移/速度限制与实际执行回执。
- [ ] 先实现传输无关的受限调用面：读能力/快照，提交/续接运动段，查询执行，暂停/恢复/取消/停止。每项定义输入/输出 schema、超时、错误码与版本兼容规则，不开放任意 Python、shell 或伺服写入。harness 校验 GPT 的结构化结果后调用本地接口；控制闭环可用后，再按需要封装 MCP。模型传输和设备传输分别适配，不把 MCP 服务部署作为最小闭环的前置条件。

### 执行生命周期与并发规则

- [ ] 分开记录请求被接受与动作完成：执行状态至少包括 queued / running / paused / succeeded / rejected / cancelled / faulted。回执含 `execution_id`、计划版本、执行起止状态、已执行前缀、剩余/作废段、终止原因；`accepted`、到达位姿和任务成功是不同事实。
- [ ] 用 `episode_id + request_id` 实现去重，同键同参数返回原回执、同键不同参数拒绝。提交后通信超时应按 ID 查询，不盲目重发增量或夹爪命令；若执行结果不可确认，保持停止并显式报告 unknown，不能假称 exactly-once 已解决。
- [ ] 使用一个调度器作为轨迹队列的唯一写入者；Astra/Luna 只提交带来源权限的计划或补丁。续接/替换必须匹配 `plan_id/version` 与预期队列尾部，原子更新；取消或换计划后，旧请求即使迟到也不能恢复执行。episode 重置必须隔离旧回执与旧结果。
- [ ] 执行前检查状态新鲜度、目标有效期、坐标/标定、数值、运动边界及 IK 条件。异步执行时允许正常状态推进，但须重新验证请求的前置条件；不能简单要求“返回时 state_seq 完全没变”，也不能只检查生成时的旧状态。
- [ ] 明确 pause 保留什么、cancel 作废什么、resume 需要什么新证据。故障停止锁存，不因迟到的 `CONTINUE` 自动解除；停止路径不依赖模型推理或模型请求队列。仿真测量停止生效前的步数/位移与夹爪保持行为，真机急停另立要求。
- [ ] 验收：用确定性假模型完成读状态、提交、续接、查询、暂停、取消；注入重复请求、响应丢失、过期计划、重置后迟到结果和非法输入，确认不重复运动、不串回合、拒绝时无意外动作。服务重启后旧执行的状态无法恢复时，标为 unknown 并禁止自动续跑。

## 建议落地顺序

1. **P0：契约与最小测量。** 固定现有基线；确定坐标/夹爪语义、计划与执行 ID、状态/回执、角色配置和失败计数。先用假模型验证去重、版本、取消；第一版调用面留在本地。
2. **P1：可靠的本地执行。** 解决 32 步截断、计划余量、轨迹与回执一致性，复用现有 IK/控制器，补可验证的保持/停止。Astra 单模型、无 RAG、同步运行先完整完成一个任务，作为后续控制器对照。
3. **P2：三层同步闭环。** 接入 Luna xhigh、阶段授权、事件路由和 Astra 升级；完成同执行器的单/双模型配对。此时可以验证分工和调用收益，尚不声称异步实时性。
