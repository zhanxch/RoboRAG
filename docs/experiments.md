# 实现阶段与验证计划

## 当前已完成：双库机制原型

使用合成记录验证长期快照只读、短期 episode 隔离、未来交互不可见、相同接口过滤、最新反馈保留及短期历史的内容检索。单元测试只证明这些软件行为；不证明机器人任务收益。

## 阶段一：真实数据入库

选择一个环境、一种机器人和少量包含抓取、对齐与插入的任务。确定原始 episode 划分，构建一份版本固定的长期库。建立真实观察和执行回执的 adapter，人工检查一组查询的候选片段，记录相关性、动作接口和几何可迁移性。

验收：每个检索片段能追溯到原始轨迹；任务划分、编码器和索引可以重建；没有测试未来信息或跨 episode 短期污染。

## 阶段二：接入固定策略与闭环执行

所有条件使用相同模型、提示模板、动作表示、执行器、相机输入和最大动作步数。先验证控制基线可运行，再只替换上下文选择方法。实时结果只写入短期库，长期库快照在整轮评测期间冻结。

首轮核心比较：

- 固定示范片段 + 最近 K 条交互。
- 长期检索 + 最近 K 条交互，用来测长期检索的作用。
- 固定示范片段 + 短期历史检索，用来测短期检索的作用。
- 长期检索 + 短期检索，即完整双库方案。

这四组都保留相同的当前观察与最新反馈，分配相同的两路预算，固定示范也从同一可用训练集选择。记录实际 token、图片和调用次数，不能仅把相同 K 当作相同上下文成本。

补充比较：无检索、随机检索、只有长期库、只有短期库、两套数据合并后的统一检索。单路实验明确是否重新分配空出的预算，同时报告固定分区和相同总预算的结果，避免混淆结构与容量收益。

## 阶段三：检索质量和经验规模

比较任务文本、当前图像、文本+图像，以及加入几何/反馈的检索。依次研究片段粒度、长期/短期配额和检索触发频率。成功与失败恢复数据的贡献单独消融；失败样本的结果标签与来源证据需明确。

固定上下文预算，逐步增加长期库规模，区分更多相关经验与更多干扰样本的影响。评测新布局、新物体或新任务时分别定义划分，避免混写为同一种泛化。

## 指标与复现

- 主要指标：完整任务成功率；另报任务进度，二者不互相替代。
- 恢复：在预定义或受控扰动触发的失败上测恢复成功率、额外动作及额外调用次数；避免只对不同方法各自留下的失败子集直接比较。
- 检索：带人工/规则标注的候选相关率、兼容率、无相关候选比例和选中记录 provenance。
- 成本：每步检索延迟、模型延迟、端到端完成时间、tokens、图片数、调用次数和缓存命中。
- 统计：多随机种子、相同任务布局/扰动，记录每个 episode 结果并报告不确定性；样本量由基线方差与算力预算决定，不预设已经显著。

保存模型/环境版本、长期快照哈希、数据划分清单、检索配置、预算策略、随机种子、每步选中记录 ID 和实际上下文成本。测试 episode 的记录不能成为同轮后续测试的长期经验；持续学习模式需单独报告任务顺序与版本变化。

## 下一步优先级

先落实真实轨迹 schema 和长期库构建，再接入 episode 短期库，随后跑固定模型下的四组比较。学习式检索、动态预算和经验晋升应在可复现基线之后开展。
