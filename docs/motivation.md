# 从 ICL 到 RoboRAG

## 叙事主线

**通过上下文适应任务 → 从经验集合中选择上下文 → 在闭环执行中动态组织两类经验。**

1. ICL 提供了通过输入示例适应任务的机制。GPT-3 的 few-shot 实验展示了无需在目标任务上进行梯度更新的适应方式。[Brown et al., 2020](https://arxiv.org/abs/2005.14165)
2. 上下文中的示例选择影响结果。基于检索的示例选择在多个语言任务上优于随机选择，说明可将“哪些经验进入上下文”作为独立研究问题。[Liu et al., 2022](https://aclanthology.org/2022.deelio-1.10/)
3. RAG 提供了将外部存储与生成模型结合的思路；这里将其扩展为机器人经验的检索与动作生成，具体有效性仍需验证。[Lewis et al., 2020](https://arxiv.org/abs/2005.11401)
4. 机器人 ICL 已探索从传感器与动作序列中推断任务。ICRT 通过专门训练得到部署时的上下文适应能力；RICL 进一步研究为已有 VLA 增加这种能力，并检索示范片段。因此不能将“检索示范用于机器人 ICL”本身作为首创主张。[ICRT](https://arxiv.org/abs/2408.15980)、[RICL](https://arxiv.org/abs/2508.02062)
5. RoboRAG 将关注点放在两类经验的协同：跨任务复用的历史经验，以及当前 episode 不断产生的现场交互。它们具有不同的生命周期、可靠性与检索目的，需要独立管理，并在有限上下文中共同参与决策。

这里的“冻结策略”指部署/评测期间不更新策略参数，不意味着底座模型从未训练，也不预设任意 VLA 天然具备 ICL 能力。首版应选择已有证据支持上下文适应的控制模型。

## 可用于 introduction 的中文草稿

上下文学习使模型能够利用输入中的示例适应新任务，而无需在推理阶段更新参数。随着这一能力从语言任务延伸到具身决策，如何提供有效上下文成为关键问题。机器人的可用经验既包括历史示范，也包括执行过程中不断产生的观察、动作与反馈；这些经验的规模持续增加，但每次决策能够使用的上下文受到容量与推理成本的约束。因此，需要根据当前任务和状态，从更大的经验集合中选择有用的信息。

机器人控制进一步要求区分经验的作用与时效。历史轨迹提供可迁移的操作方法，当前交互则包含场景特有的状态变化、执行偏差和失败原因。仅使用历史示范可能难以应对执行中出现的新状态；仅依赖当前交互又无法充分复用已有操作经验。我们提出 RoboRAG 的研究设想，通过独立的长期经验库与 episode 内短期经验库，分别检索历史操作经验与现场交互证据，并在统一的上下文预算下支持闭环动作生成。

## 核心假设

- H1：固定上下文预算及可访问数据时，状态相关的长期经验检索比固定或随机示范采样更有效。
- H2：在相同近期反馈和上下文预算下，对当前 episode 的历史进行检索比仅保留最近若干交互更有助于长程依赖和错误恢复。
- H3：长期经验与短期交互存在互补性；两路独立检索和预算分配可优于单路检索，是否优于混合检索需要消融验证。

“经验库越大效果越好”“双库一定优于单库”“无需适配即可跨机器人迁移”均不是当前结论。

## 候选贡献边界

双库是系统结构。研究贡献应通过以下问题及实验形成：

- 如何定义可迁移的机器人经验单元与状态相关性？
- 如何让历史成功示范与现场失败证据共同影响动作，而不盲目重放轨迹？
- 如何在预算约束下分配两路上下文，并保留执行所必需的即时反馈？
- 改善来自检索质量、更多可访问数据，还是更大的实际上下文？

本页是初始研究定位，不是完整的相关工作综述；新颖性判断需进一步检索和比较。
