# Sol xhigh 的 RoboICL 单回合试验

2026-10-23 按用户要求，在实现控制队列的同时测试一个既有 Astra 成功案例。
本回合已正常运行至原生 500 步上限：**Sol 获得 20 分，未完全成功**；
历史同条件 Astra 为 100 分、完整成功。见
[机器可读结果](../results/sol-roboicl-fold-clothes-l0-20261023.json)。冻结条件见
[试验计划](../experiments/sol-roboicl-fold-clothes-l0-20261023.json)。

模型根据 RGB 和机器人状态选择动作，包括回原位、等待或再次抓取；
任务是否结束以及分数由原生仿真判定。模型的动作意图不是完成证据，
未触发早停也不能单独证明某个具体评分条件失败。

## 本回合结果

- **Sol xhigh：** 500 个控制步，51 次完整模型响应，50 个有效动作决策；
  完整运行 2,950.34 秒（49.17 分钟），模型调用合计 2,760.53 秒，
  每次均值 54.13 秒、中位数 53.20 秒。
- **历史 Astra xhigh：** 247 个控制步，25 次完整模型响应和有效决策；
  完整运行 3,190.44 秒（53.17 分钟），模型调用合计 3,076.71 秒，
  每次均值 123.07 秒、中位数 125.96 秒。
- **已记录 token：** Sol 输入 4,975,757、输出 78,470，合计 5,054,227，
  其中缓存输入 331,520；Astra 输入 2,140,492、输出 58,291，合计 2,198,783，
  其中缓存输入 66,304。两者 usage 均无缺失；这些数值不等于美元费用。

Sol 第 5 次响应在第 40 步被动作校验拒绝：一个右臂旋转增量范数为 1.0 rad，
超过 0.15 rad 限值，没有产生运动。该被拒调用消耗 76,670 tokens、28.57 秒；
下一次响应在同一观测上纠正并执行了 40–50 步。开销已包含在总数内。
本回合没有传输重连，500 次已记录的 IK 连续性检查均接受。
历史 Astra 没有动作张量拒绝或 IK 连续性拒绝。

最终头部相机画面显示：袖子区域已向内折，衣服下半部仍朝桌前展开，
双夹爪停在衣摆附近。动作记录显示后半段多次尝试抓取、抬起衣摆。
这是运行结束后的可见状态描述，不是对每个内部评分谓词的独立复算。
**20 分和失败结论来自原生仿真结果。**

三路原生视频均完整解码成功，501 帧对应初始帧加 500 个控制步；
历史 Astra 的三路 248 帧也重新核验通过。运行所用冻结源码未发生变化，
本次仿真、策略服务和模型传输进程均已退出。

本例中 Sol 的单次响应更快，但用了更多控制步、更多调用和更多 token，
且未完成任务；不能据此认定它能直接替代 Astra。

## 选择与条件

选取 `fold_clothes`，standard，seed 0，layout 0。历史 Astra xhigh 在这一布局
获得原生 100 分、完整成功，执行 247 个控制步、25 次模型调用，约 53 分钟。
已发现的另一个原始 RoboICL 成功折衣回合为 310 步、32 次调用，因此优先选择前者。

本次运行原始 RoboICL dialogue policy，使用相同的一次训练示范、固定 12 个
TRAIN 块、12 个 LIVE 块、50 张图像上限，以及 10 步预测/执行 horizon。
原生预算为 500 个控制步；没有人为缩小调用或时间预算。
仅将模型请求改为 `gpt-6-sol`、`xhigh`，使用已有的已登录 CLI 传输。

它没有加载 RoboRAG 的双库检索，也没有使用本轮开发的队列执行器。
此前 `cover_blocks` 的本地 Astra 成功记录属于 dual RAG，因此没有将它当成
原始 RoboICL 对照。折衣示范使用公开训练 episode 0、官方确定性构建器；
其参考选择是此前冻结的本地扩展，不属于论文公开的冻结参考清单。

## 已核验的可比性

- 上游 commit、未提交的代码补丁、布局文件哈希均与历史 Astra 记录一致。
- 新旧完整 harness 逐字段相同；首调用提示文本、序列化输入和动作 schema
  逐字节相同；24 张 TRAIN 图像的哈希全部一致。
- 初始 LIVE 图像的渲染有轻微差异，平均 RGB 绝对差约 0.98/255，不能宣称输入
  像素完全相同。后续轨迹由各自的模型动作决定。
- 实际每次 CLI 调用的 `invocation.json` 记录模型和推理强度；传输源码复制到
  运行目录，避免并行开发更改在运行中生效。
- 运行时 GPU 上已有 ComfyUI 进程，启动时占用约 536 MiB。本试验仅启动一个仿真；
  历史与本次的墙钟时间不能作为严格受控的模型速度比较。

首选依据是本机历史原生成绩，不读取任务内部真值来决定控制动作。
单条事先已成功的任务只能验证可运行性与个例表现，不能估计总体成功率，
也不能证明 Sol 与 Astra 的一般能力等价。

## 证据与汇总

运行目录为 `runs/sol-roboicl-fold-clothes-l0-20261023/`，包含冻结启动脚本、
profile、源码哈希、初始上下文对照、逐调用输入/输出/usage、上游日志及原生结果。
原始 Astra 运行目录的绝对路径保存在冻结计划中，旧记录未改动。

```bash
python3 scripts/summarize_roboicl_trial.py \
  runs/sol-roboicl-fold-clothes-l0-20261023 \
  --output results/sol-roboicl-fold-clothes-l0-20261023.json \
  --audit-videos
```

汇总要求正常退出、原生 `status=scored`、一个匹配布局的 `_result.json`，
并检查三路视频帧数与已执行步数一致。token 统计包含被拒绝但已有 usage 的
模型调用，无法取得 usage 的调用单独列出；失败或中断回合不自动记零分。
完整模型响应不等于有效动作：`accepted_decisions` 记录通过动作校验的决策数，
`rejected_action_tensors` 记录非法动作张量，`controller_rejections` 单独统计
原生 IK 连续性检查拒绝的控制步数，缺少控制器记录时为 `null`。

通用 `scripts/run_episode.py` 同时增加 `--model`，缺省仍是 `gpt-6-astra`。
模型名称通过 policy、Responses bridge 一直传入 CLI，而不是只改变结果标签。
