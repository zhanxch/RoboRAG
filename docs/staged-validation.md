## 正式试验结束后的失败分析与处理

全部 12 例结束后，才使用动作、图像和离线原生规则分析回归；这些信息没有进入在线工具或本轮冻结前调参。

[fold standard 4 分析](../results/staged-fold-regression-analysis-81513e4.json)没有发现阶段工具错误、派发限制触发或原提示词迁移遗漏。双方均曾抓右袖失败；历史执行较早进行短移验证、按 RGB 点校正并重新闭合，候选在较长搬运后才确认失抓，再多次重抓和换腕。最终衣身形变、下摆抓宽和目标不同，模型把紧凑外形判为完成，原生仅给 20 分。保存证据不能确认唯一几何失败参数或隐藏判据，不能把这一个配对解释为某条策略的因果实验。回合在 414/500 步由环境终止，也不是步数上限耗尽。

[pour standard 5 分析](../results/staged-pour-regression-analysis-81513e4.json)确认了未满足的终局条件：倾倒后的恢复及失败交接占 267 步，比历史对应部分多 124 步，第 558 步才进入归位，右臂回家命令在 599→600 步只执行一个控制步。最终右臂末端相对初始姿态差约 73.90°，位置的 y/z 差分别约 0.234/0.195 米，明确超出原生归位容差。此容差通过离线分析确认，没有加入在线动作策略；精确关节归零与原生末端归位也不是同一个条件。空杯不能证明七球全在瓶内，这部分继续保留未知。未发现七球未知阻塞恢复、倾倒与复原经验倒置或关键操作规则缺失；主要耗费来自恢复中的 IK 限位、换手失败和再次调整。

倒球分析还发现一项独立的软件缺陷：第 0 步并行准备阶段与测量回执同时保存执行状态，固定临时文件发生 `FileNotFoundError`；模型重试后继续。它不是已证实的 600 步耗尽原因，但属于需要修复的通用竞态。`ccedc5f4ad86c279fa1899cf9fb65b6e312c1443` 为每次 JSON 发布使用唯一临时文件，并对阶段状态、事件和观测包使用不跨异步等待的可重入锁，返回脱离可变状态的快照。动作策略、SOP、prompt、图库和控制器保持原版本；149 项冻结来源与交付源码比较中只有三项实现文件变化。

[修复验证](../results/staged-persistence-repair-validation-20261027.json)包含 147 项测试通过、零跳过，ruff/格式/diff 检查通过。新增五项测试覆盖临时文件竞争与失败清理、状态写入先后顺序、返回快照，以及真实 MCP 传输下 48 个并行准备/测量/观察/状态调用。三个针对性控制在旧 `81513e4` 上分别复现临时文件错误、状态并发和快照别名问题。测试的测量回执是合成输入，不是新仿真成绩；新修复没有继承 12 例原生效果，也没有重跑失败场景。

本轮处理决定是修复已确定的通用软件缺陷，同时保留失败门槛和 legacy 默认。两处物理效果回归仍未解决；当前证据没有支持一个足够确定、值得立即新增原生试验的通用动作补丁，因此停止按单个保留场景继续试探。抓持持续验证、形变后目标对应、倒球恢复预算和返回文字精简仍是后续开发方向，需要新登记的比较范围，不能在原 12 例上调参后沿用原先的验证解释。

## 成本与结构口径

成本使用每回合原生 CLI 的累计用量，分别报告输入、缓存输入、未缓存输入、输出、reasoning、墙钟及控制步。缓存输入是输入子集；reasoning 是输出子集，不重复相加。实际美元账单与模型 API 请求次数未知；工具调用、动作段和 `turn.completed` 数量不能充当 API 次数。缺失用量保留 unknown，并在报告中区分已知下界。

三种复用单列：模型输入缓存、相同语义查询的结果缓存、阶段进入时直接复用已准备的 guidance/经验。上下文复用可能不发起新检索；高缓存输入比例也可能伴随更多未缓存输入。正式成本优先比较同场景、同条件且双方成功的配对，避免把失败或提前结束的短回合当成降本。全部尝试的实际消耗仍需保留。预注册没有强制数值降本门槛，也不能在缺少可比较证据时宣称收益。

[只读成本诊断](../results/staged-cost-diagnostics-20261027.json)在允许查看的开发日志中确认：阶段工具多次返回此前已准备的完整上下文与规则；服务端复用可以省去检索计算，但仍将这些文字送回模型，不能等同于减少模型输入。开发 push 的工具返回文字增加 69,350 字符，其中阶段生命周期相较旧检索/计划返回的增量为 60,824 字符，占 87.7%；这只是解码后文字量的算术分解，不是 token 比例、账单归因或正式回归成本变化的因果解释。开发及已完成正式汇总没有反复全量规划的证据；所查开发回合均未调用 `execution_status`，因此它的大型状态返回也不是本轮已实证的成本原因。

后续可在另行登记的改动中研究：同一上下文仍可用时返回紧凑的复用确认，以及减少评估结果对原检查项的重复回显，同时在持久记录中保留完整证据。首次使用、经验变化和上下文压缩后的恢复仍应能够取得完整 guidance；服务端缓存命中不能证明模型仍保有旧上下文。这些是待验证方向，当前 `81513e4` 冻结实现不变，也不据字符统计预估节省或追加未经登记的优化试跑。

自动核验覆盖初始计划与修订关系、SOP/索引版本、阶段进入与评估证据、动作归属与回执、观测文件哈希和派发限制的生命周期。安全停在尚未解除的派发限制可以保持记录一致；报告必须同时显示未解锁状态和最终阶段状态，不能默认为所有阶段完成。动作回执未知则另行报结构不完整。

结构一致不证明模型的每条视觉判断、经验适配或动作意图都正确。初版开发中的阶段越界正说明这一边界；修复版开发仅验证过一个实际拦截与恢复链。原生小样本不能证明无回归、通用恢复可靠性、RAG 的独立因果作用或 SOTA。

## 复核与回退

在仓库目录使用已配置的 policy Python，并将冻结 checkout 的 `src` 和仓库的 `.runtime/mcp` 加入 `PYTHONPATH`，即可重新生成离线报告。例如 fold 批次完成后：

```bash
python -m roborag evaluate-staged \
  --runs runs/staged-v1-regression-81513e4-20261027/fold_clothes \
  --task fold_clothes \
  --cases experiments/staged_v1/fold_clothes-regression.json \
  --baseline results/staged-baseline-audit-20261027.json \
  --output results/staged-regression-fold_clothes-81513e4.json
```

离线命令成功写出报告不代表验收通过，应读取 `gate` 与各回合的结构、评分和可比性字段。原生使用时省略 `--architecture staged-v1` 即沿用 legacy 默认；显式使用 `--architecture legacy` 也可回退。回退不删除新旧原始证据或改写冻结分数。
