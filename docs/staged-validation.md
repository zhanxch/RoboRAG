## 正式比较条件与冻结核对

[预注册协议](../experiments/staged_v1/protocol.json)与[冻结清单](../results/staged-regression-freeze-81513e4.json)固定以下条件：`gpt-6-astra` / `xhigh`，seed 1，delta 控制器，RAG 开启，原 `data/graph-bank/current` 图库不变。SOP、阶段索引、实际组装 prompt 与源码分别留有版本和哈希；新架构不会覆盖旧图库后沿用旧成绩。

正式场景为 fold_clothes 和 push_T 的 standard 3、4 及 random 3、4，pour_balls_into_vase 的 standard 3、4、5、6。对应历史成功数分别为 2/4、4/4、4/4。这些是本轮开发预留的历史配对场景，不能称为此前从未见过的泛化留出集。

每例只运行一次，保留失败、超时和未评分尝试，不重试取最好结果。fold/push 墙钟预算各 2160 秒，pour 为 3600 秒；原生控制步上限依次为 500、600、600。任务按 fold、push、pour 顺序运行，并行数依次为 2、2、1，全局最多两个回合。历史与本轮的服务端负载和并发环境并非完全受控，墙钟差异不构成架构导致速度变化的因果证据。

开始正式评估时独立核对了：冻结 checkout 的完整提交、协议 SHA-256、12 例列表、比较与验收字段、149 项来源哈希，以及 12 份配对基线原生结果哈希。均一致；fold 的批次预启动 `source_sha256` 与最终清单逐项一致。协议哈希为 `8e6ac4b232ef33f04e4227f877ec126881901aa192f5ad5f0fbaa81ca16597bd`。

冻结清单如实记录一次文档生成异常：初始扩展脚本传入了错误类型，扩展清单在首例启动约 31 秒后写入。批次自身已在启动前保存相同的 149 项来源哈希和比较条件；扩展清单经核对完全一致。不能把扩展文档的写入时间描述为启动前，也没有因此改动候选或比较条件。

全套正式回归完成前，人工只读取完成状态、原生结果、用量和自动结构核验输出，不查看动作/图像轨迹用于调参。顺序驱动器与各任务 `status.json` 保留批次是否完成；一个已结束回合不能代表整个任务批次已完成。

## 正式回归结果

原始批次目录为 `runs/staged-v1-regression-81513e4-20261027/`。各任务批次完成后，使用冻结版本的 `evaluate-staged` 写入 `results/staged-regression-<task>-81513e4.json`；本记录随报告更新，不用开发成绩填补正式回归空缺。pour_balls_into_vase 的正式结果仍待完成。

每个任务须四例全部获得原生评分、保留所有历史成功用例、总成功数不低于匹配基线，并通过 SOP—计划—执行证据一致性检查。没有完整证据即不算通过。该规则是工程验收门槛，不是统计等价检验。模型在线阶段判断、动作完成、任务原生评分分别保留，不能用原生成功反向把未知阶段效果改为完成。

### fold_clothes：总成功数相同，但一个基线成功用例回归

[正式报告](../results/staged-regression-fold_clothes-81513e4.json)四例均完成评分，候选和历史基线同为 **2/4**。standard 3 从历史失败变为成功，standard 4 从历史成功变为失败；random 3 双方失败，random 4 双方成功。一个改善不能抵消另一个基线成功用例的丢失，因此 `effectiveness_passed=false`、`gate.passed=false`。比较条件没有报错，`coherent_structure=true`；结构通过不能代替效果门槛。

**全部四次尝试的耗费**为 1591 控制步（均值 397.75），累计回合墙钟 2512.69 秒（均值 628.17；这是各例相加，不是并行批次耗时），输入 11,203,443 token、缓存输入 10,810,752、未缓存输入 392,691，缓存比例 96.49%；输出 50,628，含 reasoning 16,680。对应历史四例为 1493 步、累计 2883.49 秒，输入 7,848,045、缓存 7,507,968、未缓存 340,077，输出 40,463，含 reasoning 15,004。终局成功的场景组成已变化，不能把全四例较短墙钟解释为成功任务整体降本；未缓存输入和输出总量均增加。

**唯一双方成功的配对是 random 4**。历史到候选：448→401 控制步（−10.49%）、804.61→591.56 秒（−26.48%）；输入 2,145,422→2,666,338，缓存输入 2,059,904→2,569,472，未缓存输入 85,518→96,866（+13.27%）；输出 11,512→11,558（+0.40%），reasoning 4214→3552。缓存比例 96.01%→96.37%。这一个可比成功配对表现为较少控制步、较短实测墙钟，但未缓存输入更多，不能据此宣称整体降本或受控加速。

结构计数为四份初始计划、零次修订，21 次阶段准备/成功检索、零次查询缓存命中、17 次已准备上下文复用、8 次历史参考展开。122 个动作提交均有回执，未解决动作数为零。派发限制记录三次拒绝、三次解除和两次阻止动作尝试，终局均已解除。这证明所存生命周期一致，不证明所有意图或视觉判断正确。

四个回合终局仍各有 blocked 阶段；两个原生成功回合的下摆与归位在线判断也未被强行改为 complete。原生评分与在线阶段效果分别保留。当前只依据原生结果、用量和自动结构输出报告，不在全套完成前人工查看正式动作/图像，失败原因尚未分析；没有重跑或更换失败场景。

### push_T：四个指定场景保持成功，token 成本上升

[正式报告](../results/staged-regression-push_T-81513e4.json)四例均完成评分，候选与历史基线均为 **4/4 成功**，覆盖 standard 3、4 和 random 3、4。比较条件没有报错，结构检查通过，`effectiveness_passed=true`、`gate.passed=true`；`default_promotion_allowed=false`。这只表示 push 在四个登记场景通过验收，不能抵消 fold 的失败或证明更广范围无回归。

本任务全部四次尝试恰好也是四个双方成功的配对，因此成本比较覆盖所有尝试。历史到候选：控制步合计 1591→1273（均值 397.75→318.25，−19.99%），累计回合墙钟 3272.52→2262.12 秒（均值 818.13→565.53，−30.88%）；输入 7,262,777→9,322,782，缓存输入 6,972,416→8,913,280，未缓存输入 290,361→409,502（+41.03%）；输出 45,568→48,237（+5.86%），其中 reasoning 18,132→15,649。缓存比例 96.00%→95.61%。四例实测控制步和墙钟较少，但未缓存输入与输出更多；没有美元账单，也没有受控服务端负载，结论是指标方向不同，不能称整体成本改善。

结构记录为四份初始计划、零次修订，26 次阶段准备/成功检索、零次查询缓存命中、9 次已准备上下文复用、4 次参考展开。93 个动作提交均有回执，无未解决动作。random 4 记录一次阶段切换拒绝、一次动作派发拦截、一次解除；其余三例没有这些事件，所有终局派发限制均为空。四例归位阶段的在线判断均保留 blocked，原生任务成功没有将这些阶段改记为完成。这里仅报告自动核验的持久记录，不提前查看动作轨迹推断机制或原因。

## 成本与结构口径

成本使用每回合原生 CLI 的累计用量，分别报告输入、缓存输入、未缓存输入、输出、reasoning、墙钟及控制步。缓存输入是输入子集；reasoning 是输出子集，不重复相加。实际美元账单与模型 API 请求次数未知；工具调用、动作段和 `turn.completed` 数量不能充当 API 次数。缺失用量保留 unknown，并在报告中区分已知下界。

三种复用单列：模型输入缓存、相同语义查询的结果缓存、阶段进入时直接复用已准备的 guidance/经验。上下文复用可能不发起新检索；高缓存输入比例也可能伴随更多未缓存输入。正式成本优先比较同场景、同条件且双方成功的配对，避免把失败或提前结束的短回合当成降本。全部尝试的实际消耗仍需保留。预注册没有强制数值降本门槛，也不能在缺少可比较证据时宣称收益。

自动核验覆盖初始计划与修订关系、SOP/索引版本、阶段进入与评估证据、动作归属与回执、观测文件哈希和派发限制的生命周期。安全停在尚未解除的派发限制可以保持记录一致；报告必须同时显示未解锁状态和最终阶段状态，不能默认为所有阶段完成。动作回执未知则另行报结构不完整。

结构一致不证明模型的每条视觉判断、经验适配或动作意图都正确。初版开发中的阶段越界正说明这一边界；修复版开发仅验证过一个实际拦截与恢复链。原生小样本不能证明无回归、通用恢复可靠性、RAG 的独立因果作用或 SOTA。

## 复核与回退

在仓库目录使用已配置的 policy Python，并将冻结 checkout 的 `src` 和仓库的 `.runtime/mcp` 加入 `PYTHONPATH`，即可重新生成离线报告。例如 fold 批次完成后：

```bash
python -m roborag evaluate-staged \
  --runs runs/staged-v1-regression-81513e4-20261027/fold_clothes \
  --task fold_clothes \
  --cases experiments/staged_v1/fold_clothes-regression.json \
  --baseline results/staged-baseline-audit-20261027.json \
  --output results/staged-regression-fold_clothes-81513e4.json
```

离线命令成功写出报告不代表验收通过，应读取 `gate` 与各回合的结构、评分和可比性字段。原生使用时省略 `--architecture staged-v1` 即沿用 legacy 默认；显式使用 `--architecture legacy` 也可回退。回退不删除新旧原始证据或改写冻结分数。
