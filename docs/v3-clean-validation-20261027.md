# 从原始 v3 重构后的完整验证

本轮原生测试已经完成：**35/50，原版 v3 为 37/50**。预先登记的工程验收线是至少 37 例成功，因此本轮**未通过效果验收**。完整测试、软件一致性检查通过，不等于已经证明效果恢复。

实现提交为 `b2d5686c87ab49cb8d713bc75abb1341b02ff95c`，直接父提交是原始 v3 `1e9ffa05682fb750bd940938b6b8bd6bf6ac091f`。这次从原版开始拆分 MCP 模块，保留原版显式 `record_plan`、动作接口、提示词与控制器；独立监控只读取已有交互记录。没有移植阶段 SOP、graph plan、阶段准入或阶段驱动执行。

## 原生结果

全部 50 个登记场景各运行一次，50 例均得到有效原生评分，35 成功、15 失败，没有未评分例、补跑或结果替换。seed 1、标准/随机布局各 25 例，模型 `gpt-6-astra/xhigh`、delta 控制器、原始图库、并发 2、每例 1800 秒，与原版记录逐例核对一致。

- 标准布局：19/25，原版也是 19/25。
- 随机布局：16/25，原版为 18/25。
- 两版共同成功 26 例，共同失败 4 例；9 例改善，11 例回归。
- 改善：random 0、2、3、5、19；standard 2、4、17、24。
- 回归：random 7、10、11、12、13、21、23；standard 6、10、14、20。

11 例回归中，5 例用尽 500 个控制步，6 例在此前收到原生结束信号。这里描述的是日志事实；模型最终文字中对折叠、抓取或回位的判断不能替代真实图像与原生评分，也不能直接当成失败原因。

原生评分还有最终成功条件的门控：即使过程检查达到 100 分，最终 reward 未成功时也会降为 20 分。因此，20 分不能唯一定位到某项布料条件失败。原生任务在机械臂返回原位时也注册了成功检查和失败查询；“回位途中原生结束”不等于回位控制器有缺陷。现有轨迹未记录每项原生规则的真假值，不能根据分数或模型总结补造这类证据。

这些是已有的固定基准场景，每例只有一次尝试，不是未见场景上的泛化证明，也不是统计等效证明。场景 seed 没有固定模型的输出序列。

## 对齐检查说明了什么

软件检查在测试前已通过 88 项测试。全部 6 个工具的顺序、说明、schema、服务器指令和组装提示词与原版一致；18 个移动定义的 AST（含说明文本）一致。动作编译、仿真、检索和任务规则保持原版。批次入口仅补齐 seed 的透传和去重，运行记录确认最终场景与原版相同。

测试结束后，50 例原生结果文件哈希、2000 个逐例来源文件哈希、全部原版运行条件与场景文件哈希核验通过。源码、提示词、图库与登记协议在整轮期间保持冻结。全部要求的日志、计划、结果及每条命令引用的 RGB/state 快照存在；轨迹清单哈希覆盖路径和大小，不代表已逐帧验证物理语义。

追加核对发现：

- 统一临时工作目录、仓库目录和本机 MCP 端口后，50 对启动命令完全一致；其他启动参数、两类已知启动通知也一致。
- 50 对初始 `state.json` 一致。这些是模型可见的机器人状态与相机等信息，不是布料完整物理状态的证明。
- 150 对初始 RGB 均不是逐像素一致。每帧每通道的平均绝对差，整体平均为 0.376/255，最大为 0.936/255；单帧差值大于 10 的像素比例最高约 0.80%。这些差异尚不能作为成败变化的因果解释。
- 原版全部历史证据请求通过当前 MCP 回放：53 次成功检索、241 次成功动作参考和 46 次失败响应的内容一致；474 张参考图像的顺序、格式和解码后字节一致。回放没有调用模型或执行机器人动作。
- 原版有 46 次检索错误、6 次动作工具错误，本版分别为 41 和 5。原版已经存在这些错误，不能把它们的存在直接归因于此次拆分。

目前没有找到“拆分时丢失参考图像、改变工具定义、改变初始机器人状态或引入阶段约束”的证据。也不能据此断言 2 例净差距一定来自随机性：历史模型服务快照和当时 CLI 可执行文件字节没有保存，初始图像也不完全相同。需要把软件一致性与原生效果分别陈述。

## 成本

全体 50 次尝试：

- 平均控制步：原版 389.48，本版 374.38。
- 平均单例耗时：原版 474.04 秒，本版 620.55 秒。
- 总输入 tokens：原版 93,614,914，本版 88,693,616。
- 缓存输入 tokens：原版 89,768,064，本版 84,680,192。
- 未缓存输入 tokens：原版 3,846,850，本版 4,013,424。
- 输出 tokens：原版 542,667，本版 517,563；其中 reasoning 分别为 205,340 和 194,243。

在共同成功的 26 例上，平均控制步从 375.73 增至 380.50，未缓存输入从 1,961,404 增至 2,196,759，平均耗时从 458.39 秒增至 620.74 秒。因此不能凭全体平均步数或总输入降低宣称效率改善。

缓存输入已经包含在总输入中，reasoning 已包含在输出中，不重复相加。实际账单金额与模型 API 请求数未知。单例耗时之和不是并发批次总历时。

本轮记录了三次连接异常，涉及 standard/random 4、random 9/standard 10、standard/random 22；另记录 random 15 的首次响应延迟。原会话自动重试或恢复后，这些例均在原预算内完成原生评分，所有等待成本保留。网络日志不能证明其对成败的因果影响，历史运行的网络负载也没有受控。
